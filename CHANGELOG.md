# Changelog

## 0.1.0 - Unreleased
- Kitbash toolkit: Bind to Rig, Unify Surface and Apply Look share a Kitbash tab in the 3D Viewport sidebar, next to the import/export pipeline's Asset Transformer tab.
- Bind to Rig: skins every mesh in its list to the active armature with automatic weights. Use Selected adds the meshes chosen in Object Mode, including a character made of several meshes; the list is saved with the .blend file. Bones excluded from that list are stored on each mesh, turn orange in the viewport, still animate, and get no vertex group. Including a bone restores its own color. A posed bone, a non-uniform or negative scale, another parent, an unknown excluded bone, or a list that drops every deform bone fails with a clear message. The armature's license records are merged onto the mesh.
- Unify Surface: assign a tiling material to a slot, or retile it with one of three unwrap methods. Tree finds each trunk and branch (tapered, bent and capped tubes included, as well as meshes with stray duplicate faces) and seams it along one side from end to end, on a branch the side facing the trunk; other pieces are cut around their underside, or along their box sides when that would leave them too uneven to lay flat. Standard Box groups faces by the world axis they face into large upright islands. Standard Triplanar blends the texture from three axes with no seams in Blender and bakes it onto Box UVs on export, so Unity needs no custom shader. Every island gets the same texel density for the tiling texture's proportions, so thin branches match the trunk; by default that density matches the original UVs, or a Tile Size you set; the texture just tiles and is never stretched to fit, so a wrap seam may not meet exactly. A normal or mask the tiling material lacks is reported.
- Apply Look: palettes (colors sampled from a slot) and texture sets (copies of a slot's textures in `looks/textures/<category>/<name>/`) are saved separately in `looks.json` in the Blender user config, filed by category, and can be mixed freely. Surface categories (bark, rock, ...) swap in the texture set and recolor the base-color image from the palette, keeping its pattern, in seconds even for a 4096 px atlas; palettes are stored as the sRGB colors seen in the texture. Foliage is its own section: it keeps only the leaf mask and normal map and takes the palette's middle color as a material color, exported as a URP Lit cutout with that color and the mask as base map. Looks apply to the whole slot, the selected faces or a vertex group; a patch gets its own material slot with a hard edge. The slot gets a copy of its material, so other users of the original are unchanged. A looks file that cannot be read is reported and left on disk; a missing texture file fails with its path.
- Export: textures exported without library import settings (baked Triplanar maps, Blender-only images) import correctly in Unity; their minimal `.meta` was read as a legacy one, so color and normal maps imported as single-channel textures (black) or not at all.
- Export: a `.mat` copied from a library material takes its exported name inside the file too, so a retiled or recolored copy no longer shows in Unity under the original's name.
- Export: two materials from the same Unity `.mat` (for example a recolored copy next to the original) export as separate materials and textures instead of failing on a file clash.
- Animation export: when an asset and all its clips come from one library model, the FBX `.meta` gets that model's rig settings (animation type, avatar setup, root motion bone; for Humanoid, the full human description) and each clip's root motion settings (keep original position/orientation, loop blend, offsets, mirror), so root motion behaves as in the source. Re-export updates only these fields. A rig naming bones the export lacks fails with a clear message; a source whose avatar is copied from another model is left as before, with a note.
- Animation export: clips that were cut from one take moving several objects (for example an egg and its 17 shards) export back as that one take, laid end to end, with `.meta` clips cutting it by frame range under their original names and loop settings, so each clip moves all parts together in Unity. Blender keeps one action per clip. Re-export recomputes the ranges from the current action lengths and updates only those clips. A deleted or renamed clip action fails with a clear message.
- Import: a uniform scale on an imported model's top objects (0.01 for FBX in centimeters) is folded into the mesh and armature data and every location below it, keyed ones included, so exported models show scale 1 in Unity with the same size and motion. Non-uniform scales, constraints and non-armature modifiers fail with a clear message.
- Export: only the exported objects' own actions become FBX takes, so clips of other assets in the same scene no longer leak in.
- Import: LODs (`_LOD0`, `_LOD1`, ...) sharing one take that only holds a fixed transform (for example scale 0.001) get that transform baked in and the take removed; a shared take with real motion is copied per LOD.
- Animation import: an animation FBX that stores its rig as empties (for example Malbers wyvern clips) is baked onto the scene armature whose bones it names, so the clips play on that model.
- Export: a pack shader that works in URP (a `.shader` with a UniversalPipeline tag, or a `.shadergraph` with a Universal target, with all its includes and sub graphs found) is copied with its `.meta` into `<root>/Shaders/` (GUID kept), and the material keeps that shader. A shader already in the project isn't copied again. Other shaders fall back to URP Lit, and the export message lists them.
- Export: textures the source `.mat` uses but the Blender material doesn't (custom shader inputs) are copied from the library. A texture missing from the library is left empty and noted.
- Export: a source material variant becomes a plain material (its parent stays in the library).
- Export: re-export keeps an existing `.mat` and only updates its texture references, so edits made in Unity survive.
- Export: materials without a Unity source get a URP Lit `.mat` from their Principled BSDF values.
- Import: OBJ and `.blend` files also keep their real size when the scene unit scale isn't 1.
- Export: materials that came from a Unity `.mat` are written as URP Lit `.mat` files in `<Asset>/Materials/` (base color, metallic map with smoothness from alpha, normal, occlusion, emission, cutout, culling, tiling translated from the source shader) and remapped in the FBX `.meta` `externalObjects`; GUIDs stay stable across re-exports.
- Export: exported textures always get a `.meta` (GUID needed for remaps); data maps (metallic, AO, roughness) are linear.
- Import: HDRP mask maps are wired as the metallic map (R metallic, A smoothness).
- Animation import: a take that Unity splits into several clips becomes one action per clip (`<Armature>|<Clip>`, starting at frame 1, with its loop settings); the whole-take action is removed.
- Unit scale: FBX import cancels a non-1 scene unit scale so assets keep their real size; export already writes meters. The operators report the correction.
- Export: re-export drops `.meta` clips whose action was deleted or renamed; takes split into several clips in Unity are left untouched; clip names with `: `, `#` or quotes are quoted.
- Export: copied library texture `.meta` gets its own GUID (no clash when assets share a texture or the pack is also in the project); re-export keeps it.
- Export: an empty collection fails with a clear error instead of writing an empty FBX.
- Animation export: write the FBX `.meta` `clipAnimations` (frame range, Loop Time from the action's Cyclic Animation) so looping clips loop in Unity; existing `.meta` keeps its GUID and other settings.
- Animation export: take names no longer repeat the armature name (`Arm_Cat|Idle`, not `Arm_Cat|Arm_Cat|Idle`).
- Animation import: map Unity ModelImporter `clipAnimations` (loopTime / wrapMode / frame range) onto Blender actions (`use_cyclic`, manual frame range, Cycles F-Modifier).
- Animation re-import replaces the earlier copies of the same clips (so loop settings apply to the clips already in use); clip matching ignores `.001` suffixes.
- Library browser (Pack > Type > file), filename search, Open in Unity.
- Import into `Pack > Meshes` with Principled BSDF wiring from Unity `.mat`/`.meta`.
- Foliage export: when a texture (e.g. PSD) has no Blender pixels, convert/copy from the library filepath on disk instead of failing.
- Foliage export: convert PSD leaf masks to PNG with verified alpha; copy library texture `.meta` for `alphaIsTransparency`; leave FBX Opacity at 1 (Opaque Lit — no Transparent/glassy cards). True cutout needs ASFolliage remap or a Unity importer.
- Foliage export: tint leaf-mask BaseColor with ASFolliage `_Color0` and name FBX materials after the source `.mat` (Search and Remap).
- Export staging: stage collections (sidebar or Outliner), export to the active target as FBX, named textures, and `ATTRIBUTION.md`.
- Stage library Other files (shaders, etc.) from the browser and copy them into the export under `export_root/<Pack>/…` (with sidecar `.meta`).
- License detection and records on imported objects.
